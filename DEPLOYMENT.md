# Deploying JuFlow: MongoDB Atlas + Render + Vercel

```
Browser ──► Vercel (static pages from dist/)
              └─ /api/* rewrite ──► Render (Node API, server/) ──► MongoDB Atlas
```

The browser only talks to your Vercel domain. Vercel forwards `/api/*` to Render, so the login cookie is a
normal first-party `HttpOnly` cookie.

The Python files (`server.py`, `auth.py`, SQLite) are the old local prototype. They are **not** deployed.

Do the steps in this order. Each step needs a value from the one before it.

## 1. MongoDB Atlas
1. Create a free **M0** cluster (region close to Singapore).
2. Database Access → add a user with a long random password. Role: *Read and write to any database*, or scoped to `juflow`.
3. Network Access → allow `0.0.0.0/0`. Render free instances have no fixed IP, so the password is the protection.
4. Connect → Drivers → copy the `mongodb+srv://…` string and put the user and password in it. URL-encode special characters in the password.

Collections and indexes are created by the API on first boot. **Do not run `npm run seed` against production**; it is blocked when `NODE_ENV=production`.

## 2. Render (API)
1. Push this repo to GitHub.
2. Render → **New → Blueprint** → select the repo. `render.yaml` creates the `juflow-api` web service (root `server/`).
3. Fill the variables Render asks for:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1 |
   | `CORS_ORIGINS` | your Vercel URL with no trailing slash, e.g. `https://juflow.vercel.app`. The API refuses to start if this is empty, so enter your expected Vercel URL now and correct it in step 3 if it differs |
   | `ADMIN_USERNAME` / `ADMIN_PASSWORD` | the first admin login (password at least 8 characters) |
   | `CASHIER_API_TOKEN` | generated by Render. Only needed for an external device that posts to `/api/cashier/sales` |

   `NODE_ENV`, `DB_NAME`, `TZ` and `TRUST_PROXY` are already set by `render.yaml`.
4. After the first deploy, open `https://<service>.onrender.com/api/health` (expect `{"status":"ok"…}`) and `/api/ready` (expect `{"status":"ready"}`).
5. Copy the real service URL. If it is not `https://juflow-api.onrender.com`, edit the destination in `vercel.json` **and** the matching line in `tests/frontend.test.mjs`.
6. **Delete `ADMIN_PASSWORD`** from Render's environment once you can sign in. The admin is only created when none exists.

> Free Render instances sleep after about 15 minutes idle. The first request afterwards takes 30 to 60 seconds. Use the *Starter* plan if the shop needs it always on.

## 3. Vercel (frontend)
1. Vercel → **Add New → Project** → import the same repo. Leave the root directory as the repo root.
2. Framework Preset **Other**. Build command, install command and output directory come from `vercel.json` (`node scripts/build-frontend.mjs`, no install, `dist`). Do not override them.
3. Deploy. Copy the final URL.
4. If that URL differs from what you put in `CORS_ORIGINS`, fix it in Render (several origins can be comma-separated, e.g. a custom domain) and let Render redeploy. A wrong value shows up as `403 bad_origin` on every save.
5. Open `https://<your-app>.vercel.app/login.html` and sign in as the admin.

## 4. First-run checklist
1. Users → create a **Cashier** account (and Rider accounts if you use delivery).
2. Dishes → add dishes (name, picture, price), tick **Serve today**, Save.
3. Open `/cashier/` on the cashier device, sign in as the cashier, press **+** on a dish, **Apply**.
4. Open `sales.html` as admin and check the sale appears (it refreshes every 10 seconds).
5. Open the site on a second device and check customers and orders are the same.

## 5. External cashier device (optional)
`POST https://<service>.onrender.com/api/cashier/sales` with `Authorization: Bearer <CASHIER_API_TOKEN>` and a JSON body containing a unique `transaction_id`, `items[{name, quantity, price_centavos}]`, `total_centavos` (must equal the item sum) and `payment_method` (`cash`, `exact` or `gcash`; GCash needs `gcash_reference`).
- Retry with the same body → `200` with the stored sale (`duplicate: true`).
- Same `transaction_id` with different content → `409`.

The cashier web app at `/cashier/` does not use this token. It signs in with the cashier's own account.

## Security headers (`vercel.json`)
A Content-Security-Policy is set. It allows inline scripts and styles because several pages use them, so it limits where scripts, images and connections can come from but does not stop injected inline script. Allowed outside hosts: `unpkg.com` (Leaflet) and OpenStreetMap tiles. If you add a Google Maps key in `map-config.js`, also allow `maps.googleapis.com` and `maps.gstatic.com` in the policy or the map will not load.

## Environment variables (API)
See `server/.env.example`. In production the server refuses to start without `MONGODB_URI`, `DB_NAME`, `CORS_ORIGINS` and `TRUST_PROXY`.

## Known limits
- Landmark photos are stored in MongoDB (GridFS), not on Render's disk. The free Atlas tier holds 512 MB.
- Rate limiting is per IP and in memory (resets on restart). Accounts lock for 30 minutes after 5 bad passwords.
- There are no automated end-to-end tests against a real MongoDB yet. `npm test` covers the middleware and validation logic.
- Rotate `CASHIER_API_TOKEN` in Render if a device is lost.
